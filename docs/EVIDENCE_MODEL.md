# ZonePilot Evidence Model

**Reference commit:** `main` at `666ade66f965df76097c557cdf419501b683db75`.

ZonePilot's premise is that a capacity decision is only defensible if every number behind it can be
traced to what produced it, how trustworthy that thing is, and when it became knowable. That requires
two mechanisms:

1. **Evidence classes** — a closed vocabulary describing *what kind of truth* a value is.
2. **The hash chain** — cryptographic identity linking every derived artifact back to its source bytes
   and the exact code that transformed them.

Both exist today. Neither is enforced as strongly as it should be; the gaps are documented below and
are not softened.

---

## 1. The nine evidence classes

Defined in `services/temporal/contracts.py` as `EvidenceClass(str, Enum)`:

| Class | Meaning | Usable for a decision? |
| --- | --- | --- |
| `OBSERVED` | Directly measured by us or reported to us as a fact about something that happened | Yes |
| `PUBLIC_OFFICIAL` | Published by an official/authoritative body | Yes |
| `PUBLIC_GEOGRAPHIC` | Public geographic reference data (OSM road network, POIs, boundaries) | Yes |
| `PROVIDER_ESTIMATED` | A third-party provider's own estimate, not a measurement (e.g. a traffic vendor's speed estimate) | Yes, with the estimation caveat carried forward |
| `DERIVED` | Computed by ZonePilot from other evidence (e.g. an OSRM travel-time matrix from the OSM graph) | Yes, inherits the weakest class among its inputs |
| `SIMULATED` | Generated by a model or scenario, not observed | Only for scenario/what-if reasoning, never as ground truth |
| `ASSUMPTION` | A human-supplied parameter with no empirical backing | Only when explicitly surfaced to the operator |
| `STAGING_DO_NOT_USE` | Present in the system but not cleared for use | **No** |
| `TEST_ONLY` | Fixture data for tests | **No** |

Two of the nine — `STAGING_DO_NOT_USE` and `TEST_ONLY` — exist specifically so that non-decision data
has a first-class name and can never be silently promoted by being unlabelled.

### Ordering by strength

The intended precedence when combining evidence into a `DERIVED` value is:

```
OBSERVED  >  PUBLIC_OFFICIAL  >  PUBLIC_GEOGRAPHIC  >  PROVIDER_ESTIMATED
          >  DERIVED  >  SIMULATED  >  ASSUMPTION
          >  STAGING_DO_NOT_USE / TEST_ONLY (never usable)
```

**Gap:** this ordering is a documented convention. There is **no code that computes a combined
evidence class** and no propagation logic — the derivation rule is not implemented anywhere.

## 2. What is actually enforced today

### Enforced: Python contracts

`services/temporal/contracts.py` binds `evidence_class: EvidenceClass` onto `TemporalFeatureRecord`
inside a `StrictContract` base:

```python
model_config = ConfigDict(extra="forbid", frozen=True, strict=True)
```

That gives three real guarantees at construction time:

- an unknown evidence class string is **rejected** (not coerced),
- an unknown field is **rejected**,
- the record is **immutable** once built.

Alongside the class, the same contract enforces the availability timeline that makes evidence
meaningful in time:

| Invariant | Enforced in |
| --- | --- |
| every timestamp must be UTC-offset-aware | `timestamps_are_utc_aware` |
| `issued_at <= information_available_at` | `validate_availability_timeline` |
| `information_available_at <= retrieved_at` | `validate_availability_timeline` |
| every feature has exactly one unit | `validate_availability_timeline` |
| feature values must be finite | `features_are_named_and_finite` |
| **`information_available_at <= decision_time`** | `PointInTimeQuery.validity_cutoff` — the leakage boundary |

`PredictionRecord` additionally pins the provenance of a prediction: `model_version`,
`feature_dataset_version`, `graph_version`, a 40-hex `code_sha`, and a tuple of `evidence_ids`, with
`prediction_fingerprint()` producing a stable SHA-256 content hash so a rewritten prediction is
detectable.

Coverage: **10 tests** in `tests/temporal/test_temporal_foundations.py`.

### NOT enforced: the database

**This is a real gap and should be read as such.**

- **There are no database constraints on evidence class.** No `CHECK`, no enum type, no domain, no
  trigger. Nothing at the storage layer prevents an arbitrary string from being persisted as an
  evidence class.
- **Enforcement is Python-only**, which means it only holds for data that goes through the Pydantic
  contracts. Any writer that bypasses them — a direct SQL insert, a Supabase client call, a manual
  fix — is unconstrained.
- **No temporal record has ever been written through these contracts**, so the enforcement has never
  been exercised against real data. Its practical strength is currently untested.

### Enforced: the API response layer

**There is now exactly one evidence vocabulary in the system.** This was not always true, and the
drift is worth recording because it is the failure mode this model exists to prevent.

Previously the Observatory API emitted two strings that were **not** members of the nine-value enum:
`OFFICIAL_API_REAL` for the `openmeteo` and `ondc` providers, and `UNAVAILABLE` for artifacts that
were not mounted. The response contract typed the field as `StrictStr`, so both passed validation. A
**fourth** vocabulary also existed in a dead module at `services/api/core/provenance.py`.

All of it has been corrected:

| Was | Is now |
| --- | --- |
| `evidence_class: StrictStr` on Observatory responses | `evidence_class: EvidenceClass`, imported from `services/temporal/contracts.py` — an unknown string is rejected |
| `openmeteo`, `ondc` -> `OFFICIAL_API_REAL` | `openmeteo`, `ondc` -> **`PUBLIC_OFFICIAL`** (both are public/authoritative published sources) |
| `evidence_class: "UNAVAILABLE"` for absent artifacts | availability moved to a separate **`state`** field; `evidence_class` is **nullable** and is `null` exactly when `state` is `UNAVAILABLE` |
| A fourth enum in `services/api/core/provenance.py` | **deleted** |

`MapLayer` enforces the pairing with a model validator: an `UNAVAILABLE` layer must not claim an
evidence class, and an `AVAILABLE` layer must declare one. `UnavailableLayer` fixes
`evidence_class: None` in the type itself. There is no evidence to classify when there is no
observation, so the field is absent rather than borrowing a non-member value.

`DatasetRecord.schema_version` was fixed in the same pass: it now reads the **Gold manifest's own
`schema_version`** (`1.0.0`, or `null` when undeclared) instead of being populated from
`graph_version`. The field name and its contents now agree.

The TypeScript client mirrors the same closed vocabulary — `apps/observatory/src/lib/api/types.ts`
declares `EvidenceClass` as a nine-member union and types `Provenance.evidence_class` as
`EvidenceClass | null`, so Python and TypeScript cannot drift into disagreeing about what a legal
class is.

The classes that the working path emits are correct and in-enum:

| Artifact | Evidence class | Source |
| --- | --- | --- |
| Gold H3 network, road GeoJSON layers | `PUBLIC_GEOGRAPHIC` | OSM via Geofabrik |
| OSRM network snapshot, derived graph topology layer | `DERIVED` | Computed from the OSM graph |
| R1 evidence manifest itself | `PUBLIC_GEOGRAPHIC` | `services/evidence/r1.py` |

## 3. The R1 hash chain

The R1 pipeline is the one place where the evidence model is fully realised. Every artifact is
SHA-256 hashed, and `services/evidence/r1.py` **re-derives every hash from the bytes on disk** rather
than trusting the manifests.

### Chain

```
Geofabrik source
  southern-zone-latest.osm.pbf              -> source_pbf_sha256
  (MD5 verified against the published .md5 before anything else runs)
        |
        | osmium extract, bbox 77.58,12.90,77.65,12.98  (digest-pinned container)
        v
  pilot_corridor.osm.pbf                    -> clip_pbf_sha256
        |
        +-- pilot_roads.osm.pbf             -> roads_pbf_sha256
        |         |
        |         | canonical graph (networkx) + H3 R8 aggregation
        |         v
        |   gold_network_h3_8.parquet       -> gold_parquet_sha256
        |         also: graph_topology_sha256
        |                pilot_boundary_hash  (boundary_sha256)
        |                sorted_cell_list_sha256 (h3_cell_list_sha256)
        |         |
        |         | OSRM extract/partition/customize (image pinned by digest)
        |         v
        |   pilot_roads.osrm*                -> osrm_graph_bundle_sha256
        |                                       (file-set hash: name \0 bytes \0, sorted)
        |         |
        |         | executed route + 3x3 matrix
        |         v
        |   osrm_smoke_manifest.json
        |
        +-- pilot_pois.osm.pbf              -> pois_pbf_sha256
```

The OSRM graph is a multi-file artifact, so `sha256_file_set()` gives it a single identity by hashing
`relative_path \0 file_bytes \0` for each file in sorted path order.

### Assertions the evidence builder makes

`build_r1_evidence_manifest()` refuses to emit anything unless **all** of the following hold:

**Candidate binding**
- the OSM manifest, the Gold manifest, the OSRM build benchmark, and the OSRM smoke manifest each
  carry `code_sha` equal to the candidate SHA

**Content integrity**
- the recorded `source_pbf_sha256` matches the actual Geofabrik file on disk
- the OSM manifest's `clip_pbf_sha256`, `roads_pbf_sha256`, `pois_pbf_sha256` each match re-hashed bytes
- the Gold manifest's input `roads_pbf_sha256` matches the road extract actually used
- `gold.parquet_sha256` matches the re-hashed parquet
- `graph_topology_sha256` is present
- the OSRM build's `input_pbf_sha256` matches the road extract
- the OSRM build's and the OSRM smoke's `graph_bundle_sha256` both match the re-hashed bundle
- the OSRM smoke's `PBF_sha` matches the road extract

**Data quality**
- `osm.dq_status == "PASS"` and `gold.dq_status == "PASS"`
- `osm_pbf_nodes > 0`, `osm_highway_ways > 0`, `pois > 0`, gold `rows > 0`

**Routing reality**
- `distance_m > 0`, `duration_s > 0`, `finite_cells > 0`, and `null_cells == 0`

Any failure raises `EvidenceValidationError` and the workflow fails. The candidate SHA itself must be
a full 40-hex lowercase Git SHA (`ZONEPILOT_CANDIDATE_SHA`, validated by regex).

### Recorded stages

```
GEOFABRIK_DOWNLOAD -> CHECKSUM_VERIFY -> PILOT_CLIP -> CANONICAL_GRAPH -> H3_R8
-> POI -> GOLD -> OSRM_BUILD -> ROUTE -> MATRIX -> MANIFEST_AUDIT
```

### Sanitization

The emitted manifest is deliberately a **sanitized projection**: provider, source URL, retrieval
timestamp, checksum-verified flag, versions, record counts, hashes, routing smoke results, DQ status,
stages. It contains hashes rather than data, which is what allows it to be published from a private
data root into a public repository's CI artifacts.

## 4. Serving evidence

`GET /api/v1/evidence/{entity_type}/{entity_id}` resolves an entity to its provenance envelope, and
every Observatory response object carries the same fields inline:

| Field | Meaning |
| --- | --- |
| `evidence_class` | One of the nine classes above, typed as the `EvidenceClass` enum; `null` only when the paired `state` field says `UNAVAILABLE` |
| `source` | Where it came from (e.g. the Geofabrik URL, `OSRM`, `pilot_roads.geojson`) |
| `source_version` | `graph_version`, OSRM image digest, or provider source version |
| `observed_at` | Manifest `generated_at` / run completion timestamp |
| `artifact_hash` | The re-derived SHA-256 of the backing artifact |

`ArtifactCatalogRepository` re-hashes artifacts on read and raises `ArtifactCorrupt` (`409`) on
mismatch, `ArtifactNotReady` (`503`) when a manifest is absent, and `ArtifactNotFound` (`404`) for a
missing entity. Path resolution is checked so an artifact path cannot escape the configured root.

## 5. Known gaps

| Gap | Impact |
| --- | --- |
| Evidence classes are enforced by **Python and TypeScript contracts only, not by database constraints** | Any non-Pydantic writer can persist an arbitrary class string. There is no `evidence_class` column, `CHECK`, enum type, domain, or trigger in any merged migration |
| No **class-propagation / combination logic** exists | A `DERIVED` value does not automatically inherit its weakest input's class |
| **No temporal record has ever been written** | The contracts have never been exercised against real data |
| **No decision ledger** | Evidence is attached to artifacts, never to a decision — the "explain the decision" claim is not yet supported end to end |
| **No durable evidence storage** | Manifests live only in GitHub Actions artifacts with **30-day retention**; older evidence expires |
| No signature or attestation on the manifest | Integrity depends on trusting the CI run that produced it |
